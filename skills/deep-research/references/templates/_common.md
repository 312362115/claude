## 几种常见调研主题的章节顺序灵感

只列章节名顺序，每章具体怎么写看 `report-blocks.md` 的组件。

### 技术选型
```
一句话结论 → Executive Summary → 现状基线 → 候选方案概览 →
多维度对比表 → 评分雷达 → 反面观点 → 场景化推荐 → 假设验证 → 调查拓扑 → 参考资料
```

### 行业分析
```
一句话结论 → Executive Summary → 行业定义与市场规模 → 现状基线 →
主要玩家与格局 → 技术/产品趋势 → 驱动因素与风险 → 反面观点 →
机会识别 → 假设验证 → 调查拓扑 → 参考资料
```

### 概念研究
```
一句话结论 → 概念定义 → 演进脉络（Timeline） → 核心原理 →
应用场景 → 局限与争议 → 反面观点 → 实际启示 → 参考资料
```

### 性能评测
```
一句话结论 → Executive Summary → 测试范围与口径说明 →
benchmark 数据（Chart） → 横向对比表 → 影响因素分析 →
反面观点 → 适用结论 → 调查拓扑 → 参考资料
```

### 竞品分析
```
一句话结论 → Executive Summary → 自身现状基线 → 竞品速览（Card-Grid） →
功能对比表 → 定位差异（VS-Block） → 用户反馈 → 反面观点 →
差异化建议 → 参考资料
```

### 可行性探索
```
一句话结论 → 探索动机 → 现状基线（技术储备） → 验证路径 →
已知成功/失败案例 → 风险与约束 → 反面观点 → 可行性判断 → 下一步建议 → 参考资料
```

## 借鉴方式

- 内容跟范式贴合 → 借鉴章节顺序
- 内容只覆盖部分 → **删掉**用不到的章节，不要硬写
- 内容超出范式 → 自由加章节
- 章节存在的理由必须是"内容需要它"，不是"模板要求它"

---

## 反模式

- ❌ 调研类型是"技术选型"就硬塞 6 个章节全套——没有反方证据就不要"反面观点"段
- ❌ 借鉴 D1 对比表时强行凑 5+ 维度——维度按命题真正关心的来
- ❌ 调查拓扑表里 sub-agent 编号 sub-01 到 sub-99 都填——简单事实查询只需最小拓扑
- ❌ 因为这里写了"市场格局"就必须画市场格局图——没数据就别画
